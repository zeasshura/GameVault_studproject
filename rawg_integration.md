# Интеграция GameVault с RAWG API

В этом документе описывается, как наше приложение взаимодействует с внешним API [RAWG.io](https://rawg.io/apidocs), какие процессы реализованы, и как происходит синхронизация и сохранение данных (включая парсинг описаний и систему рейтингов).

---

## 1. Автоматическое заполнение базы данных (Management Command)
**Файл:** `backend/apps/games/management/commands/populate_rawg.py`

Для первичного наполнения каталога используется команда управления Django `python manage.py populate_rawg`.
- **Как работает:** Обращается к эндпоинту `GET https://api.rawg.io/api/games` с сортировкой по популярности (`ordering=-rating`).
- **Сбор данных:** Создает записи в таблице `Game` и привязывает жанры (`Genre`) и платформы (`Platform`).
- **Рейтинги:** Изначальная оценка парсится из поля `rating` (и умножается на 2 для 10-балльной шкалы), а её "вес" — из поля `ratings_count`. Это значение сохраняется в `initial_rating_count`, чтобы при добавлении пользовательских оценок средний балл рассчитывался математически верно.
- **Описания:** Поскольку списочный эндпоинт не отдает полные описания, устанавливается заглушка `(Описание загружается из RAWG при детальном просмотре)`, которая затем подгружается ленивым способом.

## 2. "Ленивая" загрузка описаний (Lazy Loading)
**Файл:** `backend/apps/games/views.py` (метод `retrieve` в `GameViewSet`)

Чтобы не перегружать API и ускорить импорт, полные описания загружаются только тогда, когда пользователь открывает страницу конкретной игры.
- **Как работает:** При запросе карточки игры (`GET /api/games/{id}/`), система проверяет поле `description`. Если оно пустое или содержит строку-заглушку, бэкенд делает запрос к `GET https://api.rawg.io/api/games/{rawg_id}`.
- **Парсинг:** При загрузке передается параметр `lang=ru`, чтобы получить русскоязычный текст. Бэкенд сначала пытается взять чистое текстовое поле `description_raw`. Если оно отсутствует, берется HTML-поле `description`, из которого с помощью `django.utils.html.strip_tags` вырезаются все HTML-теги (`<p>`, `<br>` и т.д.). Таким образом мы избавляемся от "лишних символов" при выводе на фронтенде.
- **Сохранение:** Обновленное описание сохраняется в БД (`instance.save(update_fields=['description'])`), и при последующих запросах к RAWG обращение больше не требуется.

## 3. Живой поиск игр во внешней базе
**Файл:** `backend/apps/games/views.py` (метод `search_rawg`)

Пользователи/администраторы могут искать игры напрямую в базе RAWG, которых еще нет в нашем каталоге.
- **Эндпоинт:** `GET /api/games/search-rawg/?q={query}`
- **Как работает:** Отправляет запрос поиска в RAWG API с параметрами `search` и `lang=ru`.
- **Оптимизация:** Обложки игр (`background_image`) на лету переписываются на обрезанные превью (заменяется `media.rawg.io/media/` на `media.rawg.io/media/crop/600/400/`), чтобы снизить трафик.
- **Результат:** Игры возвращаются в JSON без сохранения в локальную базу данных.

## 4. Точечный импорт игр в базу
**Файл:** `backend/apps/games/views.py` (метод `import_rawg`)

Позволяет сохранить найденную в `search_rawg` игру в локальную базу данных по её `rawg_id`.
- **Эндпоинт:** `POST /api/games/import-rawg/`
- **Как работает:** Принимает `rawg_id`, делает полный запрос к RAWG API (также с `lang=ru`).
- **Сбор данных:** 
  - Через `update_or_create` сохраняет или обновляет игру.
  - Жанры и платформы связываются автоматически.
  - Описание также проходит через безопасный парсинг `strip_tags`.
  - Извлекается оценка (`rating`) и количество проголосовавших (`ratings_count`) для `initial_rating_count`.

## 5. Интеграция с системой отзывов (Взвешенный рейтинг)
**Файл:** `backend/apps/games/models.py` (метод `update_avg_rating`)

RAWG API возвращает оценку игры по 5-балльной шкале, которую мы переводим в 10-балльную. При сохранении мы также сохраняем количество оценок с RAWG в поле `initial_rating_count`.
- **Как это решает проблему:** Ранее добавлялись только значения рейтинга без "веса". Если игра имела оценку 9.0 и один пользователь на сайте ставил ей 2.0, средний рейтинг мог упасть до абсурдных значений.
- **Текущая логика:** При добавлении или удалении ревью на нашем сайте, `avg_rating` пересчитывается по формуле взвешенного среднего:
  ```python
  total_score = сумма_оценок_с_нашего_сайта + (initial_rating * initial_rating_count)
  total_count = количество_оценок_с_нашего_сайта + initial_rating_count
  avg_rating = total_score / total_count
  ```
- **Результат:** Оценка с RAWG имеет свой изначальный вес. Пользовательские оценки плавно влияют на рейтинг, что является наиболее математически корректным подходом к объединению внешней и локальной системы оценок.
